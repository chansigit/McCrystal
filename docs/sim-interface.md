# 模拟智能体的观测和动作接口

实现在 `Server/MirEnvir/SimEnv.cs`。这份文件是它的说明;两边不一致时以代码里的常量为准,并请改这里。

每隔 `DecisionTicks` 个 tick(默认 4,即 200ms 游戏时间),环境对所有智能体做一次决策步:

1. 死了的角色自动回城复活,并记一次死亡。
2. 给每个角色填一份观测。所有角色看到的是同一时刻,之后才有人行动。
3. 策略为每个角色选一个动作。
4. 按角色编号顺序执行动作。

观测是三个扁平数组,按角色编号依次排列,行优先。这样以后交给另一个进程里的策略时不用换形状。

## 观测:局部格子 `Grid`

形状 `[13, Side, Side]`,`Side = 2 × ViewRadius + 1`。`ViewRadius` 默认 7,所以是 15×15;上限 16,即服务端发给真实客户端的范围。
角色自己在正中间。行是 y,列是 x。地图外和墙的格子所有通道都是 0。

| 通道 | 含义 |
| --- | --- |
| 0 可走 | 地形能站人则为 1(只看地形) |
| 1 被挡 | 那一格上有挡路的东西则为 1 |
| 2 怪物 | 有活着的怪则为 1 |
| 3 怪物血量 | 那只怪的血量比例,0 到 1 |
| 4 怪物等级 | 等级 ÷ 50,最大 1 |
| 5 怪物在追我 | 那只怪的目标是本角色则为 1 |
| 6 其他玩家 | 有其他活着的玩家则为 1 |
| 7 地面物品 | 有掉落物则为 1 |
| 8 NPC | 有 NPC 则为 1 |
| 9 卖药的店 | 那个 NPC 出售红药则为 1 |
| 10 收货的店 | 那个 NPC 愿意收购本角色背包里的某样东西则为 1 |
| 11 装备店 | 那个 NPC 出售或修理装备则为 1 |
| 12 可割的尸体 | 那里有一具本角色还能割取的怪物尸体则为 1 |

一格上有多只怪时,通道 3 到 5 记的是列表里最后一只。

## 观测:自身状态 `Self`

长度 30。

| 下标 | 含义 |
| --- | --- |
| 0 | 血量 ÷ 血量上限 |
| 1 | 魔法 ÷ 魔法上限 |
| 2 | 等级 ÷ 50,最大 1 |
| 3 | 当前等级的经验进度,0 到 1 |
| 4 | 是否死亡 |
| 5 | 是否在安全区 |
| 6 | 现在能不能走 |
| 7 | 现在能不能跑 |
| 8 | 现在能不能攻击 |
| 9 | 红药数量 ÷ 20,最大 1 |
| 10 | 蓝药数量 ÷ 20,最大 1 |
| 11 | 背包空格 ÷ 背包格数 |
| 12 | 负重 ÷ 负重上限,最大 1 |
| 13 | log10(1 + 金币) ÷ 7,最大 1 |
| 14 | x ÷ 地图宽 |
| 15 | y ÷ 地图高 |
| 16 到 23 | 朝向的独热编码,顺序同动作里的八个方向 |
| 24 | 背包里可卖的格数 ÷ 背包格数 |
| 25 | 身上武器的攻击分 ÷ 50,最大 1 |
| 26 | 身上衣服的防御分 ÷ 50,最大 1 |
| 27 | 武器剩余耐久,0 到 1(没有武器为 0) |
| 28 | 衣服剩余耐久,0 到 1(没有衣服为 0) |
| 29 | log10(1 + 背包里可卖物品的总卖价) ÷ 6,最大 1 |

"可卖"指不是红药,也不是"比身上好且现在就能穿"的装备。比身上好但还不满足穿戴要求的装备算可卖。
装备的评分:本职业的攻击属性(战士 DC,法师 MC,道士 SC)下限加上限,乘以 2,再加 AC、MAC 的下限和上限,加准确和敏捷。

## 动作

离散,共 41 个。八个方向的顺序是:上、右上、右、右下、下、左下、左、左上。

| 编号 | 动作 |
| --- | --- |
| 0 | 什么都不做 |
| 1 到 8 | 朝某方向走一格 |
| 9 到 16 | 朝某方向跑两格 |
| 17 到 24 | 朝某方向普通攻击 |
| 25 | 捡起脚下的物品 |
| 26 | 喝一瓶红药 |
| 27 | 喝一瓶蓝药 |
| 28 | 把附近 NPC 肯收的东西全部卖掉(保留红药和更好的装备) |
| 29 | 向附近的 NPC 买一瓶最便宜的红药 |
| 30 | 向附近的 NPC 买一件买得起、现在就能穿、提升最大的装备,并立刻穿上 |
| 31 | 穿上背包里提升最大的可用装备 |
| 32 到 39 | 朝某方向割取尸体 |
| 40 | 让附近的 NPC 修理身上磨损最重的一件装备 |

装备指武器、衣服、头盔、项链、手镯、戒指、腰带、鞋子。手镯和戒指各有两个位置,换的是较差的那个。

"附近"指 4 格以内。28 到 31 是组合动作:环境替角色完成"打开 NPC 对话、进入买卖页、逐件成交"这一串封包。

**割取。** 鸡、鹿、毒蜘蛛、食人花这几种怪死后不掉东西,肉之类的物品要对着尸体割三次才能拿到,而且只有拿到击杀的角色能割。这是 1.76 的原有机制。

## 动作掩码 `Mask`

长度 41,对应位置为 1 表示这个动作现在能做。

- 走:角色此刻能走,且目标格地形可走、没有东西挡着。
- 跑:角色此刻能跑,且前方两格都通。
- 攻击:角色此刻能攻击。不要求那个方向有怪。
- 捡:脚下有物品。
- 喝药:背包里有对应的药。
- 卖:4 格内有 NPC 肯收背包里至少一样可卖的东西。
- 买药:4 格内有卖红药的 NPC,金币够买一瓶,背包放得下。
- 买装备:4 格内有 NPC 卖一件买得起、现在就能穿、比身上好的装备,且背包有空格。
- 穿装备:背包里有比身上好、现在就能穿的装备。
- 修理:4 格内有肯修的 NPC,身上有它肯修、有磨损、修得起的装备,且背包有一个空格(服务端只修背包里的东西,环境替角色脱下、修、再穿上)。
- 割取:角色此刻能动,背包有空格,且那个方向相邻的格子(或脚下)有可割的尸体。
- 死亡的角色只能选 0。

**掩码之外的动作会被丢弃,当作 0 处理**,并计入 `RejectedActions`。原因是服务端会把来得太早的移动和攻击包排队,等能做时再执行;
不丢弃的话,这个队列会被过时的指令塞满,角色的行为就和策略当下的决定脱节了。

## 每个动作在服务端对应什么

动作被转成真实客户端发的同一种封包,注入角色的虚拟连接:`C.Walk`、`C.Run`、`C.Attack`(`Spell.None`)、`C.PickUp`、`C.UseItem`、`C.TownRevive`、`C.Harvest`、`C.EquipItem`,
以及买卖和修理用的 `C.CallNPC`、`C.SellItem`、`C.BuyItem`、`C.RemoveItem`、`C.RepairItem`。
所以移动速度、攻击间隔、负重、碰撞这些规则,都由原有的服务端逻辑判定,和真人玩家完全一样。

## 新角色的装备

新角色背包里有一把木剑和一件对应性别的布衣(`mir-176` 包的起始物品)。环境在创建时替每个角色穿上。

## 破产救济(仅模拟环境)

死亡时每件装备有 1/30 的概率掉落。低等级战士空手的伤害是 0,丢了武器又没钱就再也打不死任何怪。
所以环境加了一条游戏里没有的规则:一个活着的角色,手上和背包里都没有可用的武器,金币不到 100,背包有空格时,环境发给它一把起始武器并装上。
这条规则只作用于进程内的智能体,对正常服务器上的玩家不生效。`--sim-no-relief` 可以关掉它。

## 脚本基线

`Server/MirEnvir/ScriptedSimPolicy.cs`,用 `--sim-policy script` 启用。它只读上面这些观测,外加自己的记忆和地图本身(地形、城镇和商店的位置)。
`--sim-script-off` 可以按名字关掉它的某个部件来做对照:`flee`、`potion`、`rest`、`select`、`memory`、`resupply`。

## 还没有的东西

- 技能。动作里只有普通攻击。
- 仓库、丢弃物品、特殊修理。
- 买蓝药。
- 奖励。等级、经验、死亡次数可以从 `SimAgent` 和角色对象上读到,怎么组合成奖励在 R6 定。
- 怪物的种类。现在只给了等级和血量。
