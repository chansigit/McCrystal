# Headless MMO:开发计划与已定决策

2026-11-23 起草。分支 `headless-sim`。这份文件是给后续开发会话的交接:目标、已经定下的设计、开发阶段和已知的坑。
改动了设计或完成了阶段,就更新这里,不要另起文件。

## 目标

把 McCrystal 的服务端改造成 AI Agent 研究环境:无界面、虚拟时钟、可设种子、多世界并行,
Agent 通过宏指令参与游戏,真人仍可用原有客户端进入同一世界。正常模式和模拟模式共用同一套游戏逻辑。

当前阶段只做服务端,在本机(macOS)开发。

## 已定的设计决策

1. **世界不等 Agent。** 服务端按虚拟时钟连续推进,不做锁步。
2. **分层。**
   - 战略·慢思考:通用 LLM。决策模型置信度低时,以及需要生成文字时(聊天、谈判、长期计划)。
   - 战略·快决策:决策模型(Jev、Microsoft-Decision、pplx-decider 一类)。事件触发,从合法选项里选一条宏指令。
   - 战术:执行器,每个 tick 运行。先做脚本版,之后可换成 RL 策略(ONNX 进程内推理)。
   - 原子:现有游戏逻辑,原样复用。
3. **执行器在服务端进程内。** 它要在每个 tick 的固定位置按固定顺序运行,才能确定可复现。
   因此必须把 `PlayerObject` 和 TCP 连接拆开。
4. **两套接口。** 决策接口(宏指令下行;事件、状态摘要、合法选项上行)和控制接口(暂停、倍速、种子、重置、快照、全局统计)。
   都是独立通道,不加进游戏协议。
5. **不改 `Shared/` 里已有的封包和枚举。** 这样原生客户端和浏览器客户端都不用跟着改。
6. **倍速由谁在场决定。** 没有外部模型:越快越好。有决策模型或 LLM:中等固定倍速(用 LLM 时粗估 10 到 50 倍,未实测)。有真人:1 倍。
7. **多世界 = 多进程。** `Envir.Main` 是静态单例,`Settings` 全是静态字段,不做同进程多世界。
8. **快照分三档。** 先做指令日志重放,再做有损检查点(复用现有存盘),完整快照放最后。
9. **语言继续用 C#。**
10. **模拟模式默认不做定时自动存盘。** 只在三种时候存:关服时、控制接口显式要求时、可选的按真实时间间隔(给跑几天的 LLM 实验用)。
    模拟模式下跳过静态库 `SaveDB()` 和每次存盘的备份副本。正常模式(有真人)保留现有的自动存盘。存盘耗时未测,M0 时加计时日志。

## 重新规划(2026-11-23,M3 之后)

M0 到 M3 已完成。原计划的 M4 到 M6 被下面的 R 阶段取代,原因和新的目标如下。

**近期目标:** 在只有比奇省一张地图的世界里,训练一个能生存和练级的 RL 智能体。
真人混入、LLM 和决策模型的战略层都往后放。

**校正的依据:**

- 用户确定近期主角是 RL 训练;最初的世界只要比奇省(地图 0:87 个刷怪点,2,965 只怪)。
- 完整世界有 386 张地图、5.4 万只怪、1.5 GB 内存,对训练是浪费。单图世界预计内存和速度都好很多(待 R1 实测)。
- M4 不必把连接抽成接口。做一个没有网络的虚拟连接:进程内直接把动作包对象放进收包队列,从发包队列读结果,登录、校验、分发全部复用。
- RL 需要的是每个 tick 成批取观测、成批给动作的步进接口。这是毫秒级的同步,和"世界不等 LLM"的决策不冲突。
- MMO 自带复活机制,死亡后回城继续,所以训练可以当作持续任务,不需要重置整个世界;需要的是"把某个角色重置回 1 级"。

| 阶段 | 做什么 | 验收标准 |
| --- | --- | --- |
| R1 单图内容包 | 给 `Tools/Mir176Import` 加按地图过滤的选项,生成只含比奇省的包;去掉通往其他地图的传送 | 能启动;测出内存和空世界倍速 |
| R2 虚拟连接 | 无网络的 `MirConnection`;进程内创建账号和角色、进入游戏、重置角色 | 生成 100 个站着的角色,状态哈希可复现 |
| R3 观测和动作 | 观测:以角色为中心的局部格子(可走、怪物、玩家、地面物品)加自身属性向量。动作:离散集合(八方向走和跑、朝向攻击、喝药、捡物)。约定多少 tick 决策一次 | 接口文档定稿;随机策略能跑且可复现 |
| R4 脚本基线 | 用同一套观测和动作接口写一个脚本策略:找最近的怪、打、血少喝药、捡东西 | 脚本角色能在比奇省持续升级;作为 RL 的对照和接口验证 |
| R5 Python 桥 | 每个 tick 把所有角色的观测成批送到 Python,取回动作;包成向量化环境(一个世界里的 N 个角色就是 N 个并行样本) | 测出每秒多少个"角色步";第二个去留判断点 |
| R6 奖励和首次训练 | 奖励:经验增长、死亡惩罚等;用一个标准的 PPO 实现跑通 | 训练出的策略在升级速度或存活时间上超过随机策略,并与脚本基线比较 |
| R7 事件日志和指标 | 击杀、死亡、升级、拾取、金币变化写成结构化日志 | 能从日志画出每个角色的等级和存活曲线 |

R4 排在 Python 桥和训练之前,理由:它只要几天;没有一个已知能用的策略,训练失败时分不清是环境有 bug 还是没学会;它还是对照基线和模仿学习的数据来源。

往后放:决策模型和 LLM 的战略层、交易和行会等宏指令、多世界并行、Linux 部署(开始正式训练时会提前)、完整快照、真人混入(含模拟模式下的连接超时问题)。

训练代码用什么框架留到 R5 再定;Python 一侧按通用的 Gymnasium / PettingZoo 向量化接口做。

### M0 结果(2026-11-23,本机 macOS ARM64)

- `Server.Console` 编译通过,0 个错误。`Tests/Regression` 37 项全过。
- 用 `mir-176` 包启动成功:386 张地图,加载约 7 秒,监听 7100 和 3100。
- 空服(无玩家)常驻内存约 1.5 到 1.7 GB,CPU 约 180%(主循环加一条怪物线程,都不休眠)。
- 没拿到的数:循环耗时。管理控制台端口被占,没读到概览页;存盘计时日志也还没加。留到 M1 一起做。
- **地图文件不在仓库里。** `Packs/mir-176/Maps/*.map` 被 `.gitignore` 排除(158 MB)。新机器上要先重建,见下面"本机运行"。
- **进程收不到停止信号。** 后台运行时 `SIGTERM` 不会让它退出,只能 `kill -9`,关服存盘因此不会执行。
  `Server.Console` 只处理了 Ctrl+C。上 Linux 用 systemd 之前要补上 `SIGTERM` 处理。

之后:更多宏指令(NPC 买卖、玩家交易、拍卖、行会、说话)、决策客户端和模型接入、RL 步进接口、快照、Linux 部署。

- 模拟模式下控制台每 5 秒打印一行 `[sim]`:虚拟时间、相对真实时间的倍速、怪物数、玩家数。
- 定时存盘加了计时(`Envir.LastSaveMilliseconds`,同时写一条 debug 日志)。还没读到实际数值,5 分钟才触发一次。
- `Server.Console` 现在响应 `SIGTERM`,后台运行也能正常关服存盘。
- 验证:编译 0 错误;回归 37/37;正常模式启动和关服正常;`--sim` 下虚拟时间在走,世界里有 54,022 只怪。
- **`--sim` 现在只能跑到 1.0 倍速。** 原因是怪物线程的截止时间用"虚拟时间 + 10"去和真实秒表比较,
  虚拟时间一旦超前,怪物线程就一直跑到真实时间追上来,把倍速锁死在 1。这正是 M2 要拆的东西:
  关掉怪物多线程,去掉对象遍历的 20ms 真实时间限额和连接的每毫秒限制。

### M2 结果(2026-11-23,本机 macOS ARM64,单核)

模拟模式的主循环现在是固定步长:每次迭代时钟前进 `TickMs`,然后把全部连接、整条对象链表、全部地图各处理一次。
怪物线程在模拟模式下关闭(`Envir.UseMobThreads`),所有逻辑都在循环线程上。

空世界(`mir-176` 包,54,022 只怪,54,959 个对象,0 个玩家)不限速时:

| 构建 | TickMs | 倍速 | 每秒 tick 数 |
| --- | --- | --- | --- |
| Debug | 50 | 约 25 倍 | 约 500 |
| Debug | 100 | 约 43 倍 | 约 430 |
| Debug | 200 | 约 60 倍,波动较大 | 约 320 |
| Release | 50 | 约 44 倍 | 约 870 |

- CPU 占用 100%(一个核),内存仍是约 1.5 GB。
- `--sim-speed 5` 能把倍速稳定压在 5.0,此时 CPU 约 49%。
- 回归 37/37;正常模式启动、关服不受影响。
- 新增配置 `[Simulation] SaveMinutes`(真实分钟,默认 0 即只在关服时存)。模拟模式下不再按游戏时间定时存盘。
- 命令行:`--sim`、`--sim-speed N`、`--sim-tick N`,只对本次运行生效。

要注意的限制:

- **这是最便宜的情况。** 没有玩家时怪物周围没有目标,AI 基本空转,也没有广播。放进 Agent 后倍速会下降,要在 M5 重新测。
- **TickMs 越大越快,但动作粒度越粗。** 对象默认每 100ms 处理一次,所以 TickMs 超过 100 会改变游戏节奏。建议默认保持 50。
- **真实 TCP 连接在高倍速下会被超时踢掉。** 连接超时、保活都按 `Envir.Time` 算,这一点还没处理。模拟模式下暂时不要接客户端。
- **对象在处理中被移除时的遍历。** 当前节点和下一个节点同时被移除时,本 tick 提前结束,剩下的对象下一 tick 再处理。结果是确定的,但那些对象会晚一个 tick。

去留判断:Release 下 44 倍,空世界一天能跑约 44 个游戏日。作为起点够用,继续 M3。

### M3 结果(2026-11-23)

同一种子跑两次,一个游戏小时内每分钟的世界状态哈希完全一致。

- **随机数。** `RandomProvider.Seed(n)` 之后全世界共用一个生成器;模拟模式启动时用 `[Simulation] Seed` 播种。正常模式仍是原来的每线程生成器。
- **日历时间。** 模拟模式下 `Envir.Now` 和 `LocalNow` 从固定的 2000-01-01 起算,昼夜和跨天落在每次运行的同一个 tick 上。
- **状态哈希。** `Envir.ComputeStateHash()`:按对象链表顺序,对每个对象的 ID、种类、地图、坐标、朝向、是否死亡做 FNV-1a,怪物和人物另加血量。
  哈希里不含时间,所以相邻两次哈希不同就说明世界本身变了。
- **命令行。** `--sim-seed N`、`--sim-hash 秒数`(每隔多少游戏秒输出一行 `[hash] tick T H`)、`--sim-until 秒数`(跑到这个游戏时间就在确定的 tick 上停下并退出)。
- **控制台在引擎循环结束后会退出。** 循环异常结束时退出码为 1,不再留下一个空转的进程。

测试(Release,`mir-176` 包,空世界):

| 运行 | 种子 | 游戏时长 | 结果 |
| --- | --- | --- | --- |
| a、b | 42、42 | 3600 秒 | 60 个哈希逐行相同;60 个值互不相同 |
| a、c | 42、7 | 900 秒 | 哈希不同 |

一个游戏小时用了约 78 秒真实时间(含约 7 秒启动)。

还没覆盖的不确定来源:

- **有玩家或 Agent 时的路径都没测。** 这次只验证了空世界:刷怪、怪物游荡、定时任务。战斗、掉落、NPC 脚本要等 M5 有了 Agent 才能测。
- **`Shared` 里有三处不走种子的随机数。** 物品觉醒两处用 `new Random(DateTime.Now.Millisecond)`(`Shared/Data/ItemData.cs`),`Shuffle` 扩展用自己的静态生成器。
  1.76 内容里没有觉醒,服务端也没调用 `Shuffle`,所以现在不影响;用到时要改。
- **哈希只覆盖地图上的对象。** 背包、金币、行会、拍卖行还不在里面。
- **跨机器、跨 .NET 版本是否一致没有测。**

## 已知的坑

- **存盘间隔跟着虚拟时间变快。** 每 5 分钟存一次,在 100 倍速下是每 3 秒全量写文件。模拟模式下改为按真实时间触发或关闭。
- **连接超时、IP 封禁等也会被加速。** 模拟模式下还有真实 TCP 连接时(如旁观客户端),这些判断要用真实时间。
- **主循环的两处真实时间限额。** 对象遍历每轮最多 20ms;连接每真实毫秒处理一次。固定步长下都要去掉。
- **随机数。** `RandomProvider` 的种子取自 `Environment.TickCount`,且是 `ThreadLocal`。
- **怪物多线程。** 多条怪物线程并发时,`Envir.Objects` 的增删和对象 ID 自增没有加锁。模拟模式下关闭。
- **拆连接的改动面。** 上游代码里 `PlayerObject` 有 31 处直接用连接对象,另有 600 多处发包调用;接口要设计成调用点不用改。
- **同一内容包开多个实例时端口冲突。** 端口写在包的 `Configs/Setup.ini` 里,`--state` 只分开了运行状态。
- **macOS 上 AirPlay 也占 7000 端口。** `mir-176` 用 7100,不受影响。见 `docs/project-status.md`。

## 本机运行

第一次在一台机器上运行,要先重建地图(从 GPL-3.0 的 Mir2-GeeM2 仓库取 1.76 基线,再跑导入工具):

